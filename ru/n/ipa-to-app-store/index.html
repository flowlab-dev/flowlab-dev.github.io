Файл .ipa готов, а Mac нет? Приложение все равно попадет в App Store.

Base44 и похожие конструкторы выдают файл .ipa и на этом останавливаются. Apple принимает его только с Mac и свежим Xcode. Mac для этого не нужен. Небольшой сценарий в вашем собственном GitHub загружает файл на серверах Mac от GitHub штатным инструментом Apple. Ключ App Store остается в вашем аккаунте, доступа к нему у нас нет.

Порядок работы

#ШагКто
1Вы получаете один файл сценария для нового закрытого репозитория GitHub. Сначала сценарий проверяет .ipa инструментом Apple, затем загружает его и удаляет ключ с сервера.Flow Lab
2Вы создаете ключ API в App Store Connect (роль «App Manager») и добавляете его в секреты репозитория. Пошаговая инструкция прилагается: где нажать в App Store Connect и в GitHub.Вы, около 10 минут
3Первая загрузка проходит вместе: вы нажимаете «Run workflow» и присылаете журнал запуска (секреты GitHub в нем скрывает). Все замечания проверки Apple исправляем сразу.Вместе
4После обработки в Apple сборка появляется в App Store Connect → TestFlight. Следующие обновления: новая ссылка на .ipa → «Run workflow».Готово

Что понадобится

  • Аккаунт Apple Developer (Apple берет 99 USD в год, это плата Apple, а не наша) и карточка приложения в App Store Connect с тем же bundle ID, что у вашего .ipa.
  • Файл .ipa из вашего конструктора (достаточно ссылки на скачивание).
  • Бесплатный аккаунт GitHub.

Честно о границах

  • Этот способ загрузки описан в документации Apple (Apple: загрузка сборок). Настройка и первый запуск проходят вместе, в вашем аккаунте. Доступа к вашему аккаунту у нас нет, поэтому заранее загрузить за вас нельзя. Для клиента такую загрузку мы еще не делали.
  • Если .ipa не подписан для App Store, проверка Apple сообщит об этом до загрузки. Подпись исправляется в настройках вашего конструктора.
  • Подписки внутри приложения настраиваются отдельно: в Base44 и похожих конструкторах покупок Apple по умолчанию нет. Если они нужны, напишите.
