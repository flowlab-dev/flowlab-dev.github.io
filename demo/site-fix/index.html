Site fix, measured

Same roofer, same content. Now it works on a phone.

This is a worked example on an invented business: the “before” site was built with problems that are common on small-business sites, then fixed and measured. It looked passable on a desktop. On a phone it was slow to load, the text was too small to read, the phone number was a line of text about 6 px high with no call button, and the contact form lost every enquiry. Here is the fix, measured before and after the same way.

What a visitor on a phone sees

The first screen of each version, loaded on the same phone-sized browser.

The numbers

Measured on a phone-sized browser over a slow mobile connection, with the processor slowed four times, the way Lighthouse imitates a mid-range phone. Each version was loaded three times with an empty cache; the table shows the middle result. Both ran on a local test server, so real hosting would add some time to both.

What was fixed

Nothing was redesigned: same sections, same pictures, same font. The text was tightened a little, grey text made darker, and the buttons given one brand colour. Each fix is small on its own.

How it was measured

Both versions are served from one local server and opened in headless Chrome set to an iPhone screen size (390 × 844). The connection is slowed to 150 ms latency and 1.6 Mbit/s, and the processor to a quarter of its speed, so the numbers are closer to a phone on weak 4G than to a laptop on Wi-Fi. “Time until the main picture appears” is the browser’s Largest Contentful Paint. The form was sent once to a test endpoint on the same server, which recorded the enquiry; on a real site it would go to the owner’s inbox. The checks in the last row come from the same script I run on a real site before I write to its owner.
