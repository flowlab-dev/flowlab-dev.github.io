Make.com scenario rescue · demo case

Urgent quote requests now go to the on-call tech, the rest to sales.

A website quote form feeds a Make scenario: it logs the request, looks up the service area, alerts the on-call tech about urgent jobs and emails sales about the rest. Most runs look fine in History. The audit produced 11 findings, 6 of which affected lead delivery and alert fields. All 11 are now closed.

Demo scenario built for this case, modeled on a typical home-services lead flow. Not a client's scenario.

What was found and fixed

HIGH · lead delivery

A step now waits and retries, and the scenario stays on

Before the fix, "Allow storing of incomplete executions" was off. A run stopped at Google Sheets, Slack or Gmail could not be retried, because the website does not resend a form. With the default error settings, Make also switches off a webhook-triggered scenario right after its first error.

Fix: incomplete executions on, plus Break handlers with automatic retry on the Sheets, Slack and Gmail steps. If one of these steps does not go through, it now waits and retries, and the scenario keeps running.

HIGH · alert fields

"Area" now always shows the service area or a clear note

Before the fix, the ZIP lookup ran on the legacy HTTP module with "Evaluate all states as errors" off. Make read a 401 or 500 reply from the API as the service area.

Fix: the current HTTP "Make a request" module with "Return error if HTTP request fails" on, and a Resume handler that writes "area lookup failed, check ZIP". The lead reaches sales with this clear note.

HIGH · security

The API key now lives in a Make keychain

Before the fix, the live key sat in the module URL and travelled with every exported blueprint, for example to a freelancer or in a shared template.

Fix: key moved into a Make keychain (API key authentication in the HTTP module), so it never appears in an export, and the old key rotated.

HIGH · alert fields

Two fields now take data from a step that always runs

Before the fix, the Slack alert took "Quote #" from the Gmail module on the other route, and the sales email took a field from a deleted module, so both always came out empty.

Fix: both now use the Google Sheets row number from the "Log request" step, which runs before the router on every path.

MEDIUM · sales emails

Sales now get one email per request

Before the fix, an iterator over "services" fed Gmail directly: three ticked services meant three near-identical emails. The manual review added the case of no services ticked, where the iterator had nothing to pass on and no email was sent.

Fix: no iterator. The email lists the services with join() and says "not specified" when the list is empty: one request, always one email.

HIGH · routing, found in manual review

"Urgent" and "urgent" now take the same route

Before the fix, the router filters matched "urgent" and "standard" exactly, letter case included, and there was no fallback route. A form value of "Urgent", or an empty value, was written to the sheet but matched neither route.

Fix: case-insensitive match for "urgent", and the sales route became the fallback route: anything not urgent reaches sales.

LOW · sheet format

Dates and numbers now sort and filter in Sheets

Before the fix, rows went into Sheets as plain text.

Fix: valueInputOption: USER_ENTERED.

The audit report

The first pass is an automatic review of the exported blueprint. It needs only the file, with no run of the scenario and no login to your accounts. Next comes a manual review of the logic, and every item is confirmed in the editor before any change is made. Excerpt:

Make scenario review: Quote requests → Sheet → Sales alerts (BEFORE)
7 modules, trigger: instant (webhook).

1. HIGH - Scenario settings: "Allow storing of incomplete executions" is off and the scenario starts with a webhook. If any module returns an error, the run stops and the request is not stored for a retry. With default settings, Make deactivates an instant-trigger scenario immediately after its first error.
2. HIGH - "ZIP → service area" [3]: "Evaluate all states as errors" is off: a 4xx/5xx reply is read as success.
4. HIGH - "Alert on-call tech" [5]: Maps a field from "Email sales" [7], which is not on the path before this module. On this path the field is always empty.

AFTER: all automatic checks pass. (Manual review: done.)

The blueprints are written by hand for this demo to show how the fix is built. They are shown as files, without an import into Make, and the module settings are illustrative. On a real job every change is made and tested in your own account.

How a rescue works

  1. You export the scenario: in the editor, … (More) → Export Blueprint, and send the .json file. No login needed for the first look.
  2. Within one business day: a plain-English list of what to fix, how it affects your business, and the proposed changes.
  3. You approve the changes. Flow Lab then fixes the scenario in your account, runs test submissions through every route and shows you the results.
  4. Optional monthly support: ongoing scenario monitoring and fixes for new errors.
