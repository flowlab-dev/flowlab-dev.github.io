Аудит готовности к выпуску в магазины приложений: FieldCrew

Стек: Expo ~53.0.9 · React Native 0.79.2 · TypeScript · тестов: 0 · lock-файл: yarn.lock

Идентификатор iOS: com.example.fieldcrew · имя пакета Android: com.example.fieldcrew

Обязательно до выпуска: 3 · исправить: 10 · заметки: 3. Для проверки нужны только файлы проекта: ничего не устанавливается и не запускается.

УровеньРазделОписаниеЧто сделать
🔴СтекПроект использует Expo SDK 53, а актуальная версия, SDK 57, новее на 4 версии. Для публикации в магазинах сейчас нужны свежие версии Xcode и iOS SDK и актуальный целевой уровень Android API. Со старой версией Expo SDK эти требования обычно не выполнить.Обновить SDK поэтапно, с 53 до 57, исправить несовместимости и заново проверить приложение.
🔴БезопасностьВ проекте есть файл .env, а в .gitignore пока нет правила, которое исключает такие файлы из репозитория.Убрать файл .env из репозитория, сменить ключи и добавить .env* в .gitignore.
🔴БезопасностьВ src/billing/config.ts, по всей видимости, хранится секретный ключ (Stripe live secret key).Перенести ключ на сервер или в секреты EAS и сменить его. Все, что встроено в приложение, может прочитать любой человек.
🟡НастройкиИдентификатор iOS «com.example.fieldcrew» похож на шаблонный.Выбрать окончательный идентификатор до первой загрузки в магазин: после нее он закрепляется за приложением навсегда.
🟡НастройкиИмя пакета Android «com.example.fieldcrew» похоже на шаблонное.Выбрать окончательное имя пакета до первой загрузки в магазин: после нее оно закрепляется за приложением навсегда.
🟡СборкаВ проекте пока нет файла eas.json, поэтому облачная сборка не настроена.Добавить профили сборки EAS: для разработки, для тестирования и для магазинов.
🟡App StoreЗначок сейчас размером 512×512 пикселей, а App Store требует 1024×1024 пикселей.Сохранить значок в размере 1024×1024.
🟡App StoreУ значка есть прозрачность, а значки для App Store должны быть непрозрачными.Разместить значок на сплошном фоне.
🟡Google PlayАдаптивный значок Android пока не настроен.Добавить adaptiveIcon: изображение переднего плана и цвет фона.
🟡App StoreApp Store Connect при каждой загрузке спрашивает, использует ли приложение шифрование, а ответ на этот вопрос в настройках приложения пока не указан.Задать ios.config.usesNonExemptEncryption (обычно false, если приложение использует шифрование только в HTTPS).
🟡App StoreПриложение использует expo-camera, а текст запроса доступа к камере в iOS (NSCameraUsageDescription) пока не задан. App Store часто отклоняет приложения с общими шаблонными текстами разрешений (правило 5.1.1).Написать для каждого разрешения конкретное объяснение, зачем оно нужно.
🟡App StoreПриложение использует expo-location, а текст запроса доступа к геопозиции в iOS (NSLocationWhenInUseUsageDescription) пока не задан. App Store часто отклоняет приложения с общими шаблонными текстами разрешений (правило 5.1.1).Написать для каждого разрешения конкретное объяснение, зачем оно нужно.
🟡БезопасностьВсе значения из раздела «extra» в настройках приложения встраиваются в само приложение. Сейчас в этом разделе лежит supabaseServiceKey.Оставить в extra только открытые значения.
⚪СборкаПри установке зависимостей скрипт postinstall запускает «patch-package», распространенный инструмент.
⚪App StoreExpo сам добавляет манифест приватности для своих модулей, а манифест приватности самого приложения пока не заполнен.Описать в нем сбор данных и API, для которых Apple требует указать причину использования, если их использует приложение или подключенные библиотеки.
⚪КачествоПроверка не нашла в проекте автоматических тестов.Перед доработками добавить тесты для ключевой логики приложения.

По оценке, работа до сборки, готовой к публикации в магазинах, займет около 21 часа: исправления из таблицы, настройка EAS и первые сборки. Аккаунты магазинов (Apple Developer, Google Play) остаются у владельца, и приложение публикуется с его аккаунтов.

План по шагам

  1. Первым делом убрать ключи и секреты из кода и репозитория и сменить их.
  2. Обновить Expo SDK и зависимости, исправить несовместимости, проверить приложение.
  3. Выполнить пункты уровня «Исправить»: тексты разрешений, значки, шифрование, настройки сборки.
  4. Настроить облачную сборку EAS и собрать тестовые версии iOS и Android.
  5. Проверка на ваших устройствах: TestFlight (iOS) и внутреннее тестирование (Google Play).
  6. Отправка на проверку в App Store и Google Play с ваших аккаунтов и ответы на замечания проверяющих.
