The case

A support chatbot is easy to build. Companies worry about something else. A bot that invents a refund policy costs more than all the support time it saves.

The demo shows how the assistant handles 74 difficult questions.

The setup. Shiftbloom is an invented company that makes shift-scheduling software. Its help center was written for this demo: 7 documents with 33 sections. They cover pricing, scheduling, integrations, security and support. The assistant answers from that material and nothing else.

Three honest outcomes. It answers and shows the source underneath. Or it asks which topic you meant. Or it says the help center does not cover this and hands you to a person. There is no fourth option. Nothing inside it writes new text, so it cannot invent an answer even by accident.

It understands how people really type. Questions arrive with typos, half-remembered wording and words the documentation never uses. The assistant corrects spelling against its own vocabulary and understands synonyms. Before it answers, it checks how much of the question a page actually covers. A question made only of common words cannot pull a confident reply from an unrelated page.

Tests confirm the quality. A fixed set of 74 questions runs from a button on the demo page. It includes real phrasings, typos, paraphrases and questions the assistant must refuse. All 74 pass. Every wrong answer found during the build became a test. A fixed mistake cannot return unnoticed.

The demo runs entirely in the browser, with no server, API key or account.

In a real project, the assistant answers from your own materials and sits on your site. You get the test questions as a file you can read yourself.
