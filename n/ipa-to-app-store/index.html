Your .ipa is ready but you have no Mac? Upload it to the App Store anyway.

Base44 and similar builders give you an .ipa file, and then stop. Apple wants it sent from a Mac with a recent Xcode. You don’t need one: a small workflow in your own GitHub uploads the file for you on GitHub’s Mac servers, with Apple’s own upload tool. Your App Store key stays in your account, and we never see it.

What we do

#StepWho
1We send you one workflow file for a new private GitHub repository. It checks the .ipa with Apple’s tool first, then uploads it, then deletes the key from the server.Flow Lab
2You create an App Store Connect API key (role “App Manager”) and paste it into your repository’s secrets. We send step-by-step instructions: where to click in App Store Connect and in GitHub.You, ~10 min
3We run the first upload together: you press “Run workflow”, we read the log with you and fix anything Apple’s check flags.Together
4After Apple processes the upload, the build shows up in App Store Connect → TestFlight. Next updates: new .ipa link → “Run workflow”.Done

What you need

  • An Apple Developer account (Apple charges USD 99 a year; that’s Apple’s fee, not ours) and an app record in App Store Connect with the same bundle ID as your .ipa.
  • The .ipa from your builder (a download link is enough).
  • A free GitHub account.

Honest notes

  • This is the method Apple documents for uploads (Apple: upload builds). We set it up and do the first run together on your account. We don’t have your account, so we can’t upload for you in advance, and we haven’t done this upload for a client yet.
  • If the .ipa isn’t signed for the App Store, Apple’s check says so before anything is uploaded; that part is fixed in your builder’s signing settings.
  • In-app subscriptions are a separate topic: builders like Base44 don’t include Apple’s purchase flow out of the box. Ask us if you need it.
